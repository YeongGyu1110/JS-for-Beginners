# HTML과 웹 브라우저의 동작 원리

## 개요
우리가 매일 접속하는 포털 사이트, 쇼핑몰, SNS 등의 웹 페이지를 열었을 때 화면에 나타나는 텍스트, 이미지, 버튼들은 도대체 어떻게 만들어져 우리 눈앞에 보여지는 것일까요? 웹 개발의 세계에 발을 들일 때 가장 먼저 만나게 되는 기술이 바로 **HTML**입니다.

본 문서에서는 웹 페이지의 뼈대를 구성하는 HTML의 근본적인 개념을 알아보고, HTML이 왜 프로그래밍 언어가 아니라 '마크업 언어'로 분류되는지 그 이유를 살펴봅니다. 더 나아가, 텍스트에 불과한 HTML 코드를 우리가 보는 화려한 웹 화면으로 탈바꿈시켜 주는 **웹 브라우저의 렌더링(Rendering) 원리**에 대해 상세히 다룹니다.

### 이 문서에서 배울 내용
* HTML(HyperText Markup Language)의 역할과 개념
* HTML이 프로그래밍 언어가 아닌 마크업 언어(Markup Language)인 이유
* 꺾쇠 괄호(`< >`)로 이루어진 태그(Tag)의 기본 구조
* 브라우저가 HTML 문서를 읽고 가상의 트리(DOM)를 만들어 화면에 그리는 과정

---

## 1. HTML이란 무엇인가?

HTML은 **H**yper**T**ext **M**arkup **L**anguage의 약자로, 웹 페이지의 구조와 내용을 정의하는 가장 기초적인 언어입니다.

건물을 지을 때 가장 먼저 철골을 세워 뼈대를 잡는 것처럼, 웹 개발에서는 HTML을 사용하여 "여기는 제목이 들어갈 자리", "여기는 이미지가 들어갈 자리", "여기는 클릭할 수 있는 버튼"이라고 웹 페이지의 <b>뼈대(구조)</b>를 설계합니다. 

단순한 텍스트 파일(메모장 등)에 HTML 문법에 맞게 글을 작성하고 저장한 뒤 크롬(Chrome)이나 엣지(Edge) 같은 웹 브라우저로 열면, 브라우저가 그 문서를 해독하여 보기 좋은 웹 페이지로 만들어 줍니다.

---

## 2. 왜 '프로그래밍 언어'가 아닐까?

웹 개발을 처음 접하는 많은 사람들이 "나는 HTML로 프로그래밍을 해!"라고 말하곤 합니다. 하지만 컴퓨터 공학적으로 HTML은 <b>프로그래밍 언어(Programming Language)</b>가 아닙니다. 그 이름에서 알 수 있듯 <b>마크업 언어(Markup Language)</b>입니다.

### 프로그래밍 언어의 특징
프로그래밍 언어는 컴퓨터에게 <b>'어떻게 행동할지(Logic)'</b>를 지시합니다. "만약(if) 이 조건이 맞으면 이것을 하고, 저 조건이 맞으면 저것을 10번 반복(for)해라"와 같이 계산, 조건부 판단, 반복 연산 등의 논리적인 흐름을 제어하는 능력이 필수적입니다.

### 마크업 언어의 특징
반면 HTML은 계산을 하거나 조건을 판단하는 능력이 전혀 없습니다. 1 더하기 1을 계산할 수도 없습니다. 마크업(Markup)이라는 단어는 원래 출판업계에서 원고의 교정지에 "이 부분은 굵은 글씨로", "이 부분은 큰 제목으로"라고 형광펜이나 빨간 펜으로 **표시(Mark)를 남기던 작업**에서 유래했습니다.

즉, HTML은 데이터가 <b>'무엇인지'</b>에 이름표를 붙여주는 역할만 합니다.
* *"이 텍스트는 중요한 제목이야."*
* *"이 텍스트는 다른 페이지로 이동하는 링크야."*

이렇게 정보의 구조와 의미를 브라우저에게 설명(표시)해 주는 언어이기에 마크업 언어라고 부릅니다.

> [!NOTE]
> HTML 스스로는 움직이거나 계산할 수 없기 때문에, 웹 페이지에 생동감을 불어넣고 논리적인 연산을 수행하기 위해서는 자바스크립트(JavaScript)와 같은 '진짜 프로그래밍 언어'를 HTML과 함께 결합하여 사용해야 합니다.

## 3. 꺾쇠와 태그 (Tag)

HTML은 데이터에 이름표를 붙이기 위해 <b>태그(Tag)</b>라는 특별한 문법을 사용합니다. 태그는 항상 꺾쇠 괄호 `< >`로 감싸져 있습니다.

데이터를 태그로 감싸는 것은 마치 내용물을 알맞은 상자에 넣고 포장하는 것과 같습니다.
* **시작 태그:** `<태그이름>` 형태로 상자를 엽니다.
* **종료 태그:** `</태그이름>` 형태로 슬래시(`/`)를 넣어 상자를 닫습니다.

```html
<!-- h1 태그는 가장 큰 제목(Heading 1)을 의미하는 이름표입니다. -->
<h1>이것은 제목입니다</h1>

<!-- p 태그는 하나의 문단(Paragraph)을 의미하는 이름표입니다. -->
<p>이것은 본문 텍스트입니다. 태그로 감싸진 글자들은 브라우저에 의해 알맞게 해석됩니다.</p>
```

어떤 태그를 쓰느냐에 따라 브라우저는 안의 내용물을 글자로 보여줄지, 표(Table)로 보여줄지, 텍스트 입력창으로 보여줄지 결정하게 됩니다.

## 4. 브라우저는 어떻게 화면을 그릴까? (렌더링 원리)

우리가 작성한 HTML 코드는 그저 영단어와 꺾쇠가 섞인 단순한 텍스트일 뿐입니다. 이 텍스트 덩어리를 우리가 보는 시각적인 화면으로 바꿔주는 브라우저 내부의 핵심 과정을 <b>렌더링(Rendering)</b>이라고 부릅니다.

브라우저가 HTML을 받아 화면에 그리기까지는 크게 3단계의 마법 같은 과정을 거칩니다.

### 1단계: 파싱 (Parsing, 구문 분석)
브라우저는 우리가 작성한 HTML 문서를 맨 윗줄부터 아래로 한 줄씩 순서대로 꼼꼼히 읽어 내려갑니다. 이 과정을 파싱이라고 합니다. 코드를 읽으면서 시작 태그와 종료 태그를 짝지어 분석하고, 문법에 오류가 없는지, 어떤 텍스트가 어떤 상자(태그)에 담겨 있는지 해독합니다.

### 2단계: DOM 트리 (DOM Tree) 구축
파싱을 마친 브라우저는 해독한 정보들을 바탕으로 컴퓨터의 메모리상에 <b>거대한 족보(가계도) 같은 가상의 트리 구조</b>를 만들어 냅니다. 이를 <b>DOM(Document Object Model)</b>이라고 부릅니다.

HTML 태그들은 상자 안에 또 다른 상자를 넣을 수 있는 구조(부모와 자식 관계)를 가집니다.
예를 들어 `문서`라는 거대한 뿌리(Root) 아래에 `제목` 가지와 `본문` 가지가 뻗어나가는 식입니다. 브라우저는 글자를 있는 그대로 이해하는 것이 아니라, 이렇게 구조화된 DOM 트리를 생성하여 데이터를 인식합니다.

### 3단계: 페인팅 (Painting) / 렌더링
DOM 트리가 완성되면, 브라우저는 이 가상의 뼈대(트리)를 바탕으로 모니터라는 도화지에 **실제로 픽셀(Pixel) 단위로 색을 칠하고 그림을 그리기 시작**합니다. 제목 태그는 크고 굵은 글씨로 화면 상단에 그리고, 문단 태그는 그 아래에 적당한 크기로 배치하여 우리가 최종적으로 보는 웹 페이지 화면을 완성해 냅니다.

> [!IMPORTANT]
> **위에서 아래로 읽어 내려가는 특성**
> 브라우저는 HTML 문서를 무조건 맨 위에서부터 아래로 읽어 내려갑니다(파싱). 따라서 코드를 작성할 때 순서가 매우 중요합니다. 브라우저가 아직 읽지 못한 아래쪽의 태그를 화면에 먼저 보여주거나 조작할 수는 없습니다. 이 특성은 나중에 다른 웹 기술들을 결합할 때 스크립트를 어디에 배치할지 결정하는 아주 중요한 기준이 됩니다.
