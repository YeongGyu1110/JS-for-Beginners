# 폼과 사용자 입력 (Form)

## 개요
지금까지 배운 텍스트, 이미지, 링크 등의 태그들은 모두 웹사이트가 사용자에게 일방적으로 정보를 '보여주는(Output)' 용도였습니다. 하지만 인터넷은 단방향 통신이 아닙니다. 우리는 구글에 검색어를 입력하고, 네이버에 아이디와 비밀번호를 쳐서 로그인을 하며, 쇼핑몰에서 배송지 주소를 적어 넣습니다.

이렇게 **사용자가 직접 데이터를 입력하고, 그 데이터를 웹 서버로 전송하기 위해 사용하는 양식**을 <b>폼(Form)</b>이라고 부릅니다. 

본 문서에서는 사용자와 웹사이트가 상호작용하는 가장 핵심적인 창구인 폼의 기본 구조를 알아보고, 텍스트 입력창부터 체크박스, 드롭다운 메뉴까지 다양한 형태의 입력 도구들을 화면에 만들어내는 방법을 상세히 학습합니다.

### 이 모듈에서 배울 내용
* 입력 데이터를 하나로 묶어 서버로 배달하는 상자 `<form>` 태그
* 데이터를 전송하는 방식의 차이 (`GET` vs `POST`)
* 카멜레온처럼 모습을 바꾸는 `<input>` 태그의 다양한 `type` 속성들
* 사용자의 편의성과 웹 접근성을 높여주는 `<label>` 태그의 마법
* 긴 글을 쓰는 `<textarea>`와 선택 메뉴를 만드는 `<select>` 태그
* 폼의 완성도를 높이는 유용한 속성들 (`name`, `placeholder`, `required`)

## 1. 데이터를 담는 배달 상자: \<form\> 태그

웹 페이지에 입력창을 만들려면, 가장 먼저 이 입력창들을 하나로 묶어줄 거대한 껍데기인 <b>`<form>` 태그</b>를 만들어야 합니다. `<form>`은 사용자가 입력한 여러 개의 데이터를 하나의 '택배 상자'에 담아 서버(우체국)로 보내는 역할을 합니다.

택배를 보낼 때 주소지와 배송 방법이 필요하듯, `<form>` 태그에는 두 가지 아주 중요한 속성이 들어갑니다.

* **`action` (목적지):** 사용자가 폼을 제출했을 때, 이 데이터 상자를 받아서 처리할 <b>서버 측의 프로그램 URL</b>를 적습니다.
* **`method` (전송 방식):** 데이터를 서버로 전달할 때 사용할 방식을 정합니다. 대표적으로 `GET`과 `POST`가 있습니다.
  * **`GET`:** 검색창처럼 보안이 중요하지 않은 데이터를 보낼 때 씁니다. 보낸 데이터가 웹 브라우저의 주소창에 그대로 노출됩니다. (예: `?search=사과`)
  * **`POST`:** 로그인 비밀번호나 개인정보처럼 보안이 필요한 데이터를 보낼 때 씁니다. 데이터가 주소창에 보이지 않게 상자 안쪽에 꽁꽁 숨겨서 안전하게 보냅니다.

```html
<!-- 사용자가 제출 버튼을 누르면, 상자 안의 내용물이 POST 방식으로 /login.php 주소로 전송됩니다. -->
<form action="/login.php" method="POST">
    <!-- 이 안에 입력창(input)과 제출 버튼이 들어갑니다. -->
</form>
```

## 2. 변신하는 입력창: \<input\> 태그

`<form>` 상자 안에 들어갈 실제 내용물, 즉 사용자가 글자를 치거나 체크를 할 수 있는 입력 칸은 대부분 <b>`<input>` 빈 태그</b> 하나로 만듭니다. 

`<input>` 태그는 <b>`type` 속성</b>에 어떤 값을 주느냐에 따라 텍스트 상자, 비밀번호 상자, 체크박스 등 카멜레온처럼 그 모양과 기능이 완전히 바뀝니다.

* **`type="text"`:** 가장 기본적인 한 줄짜리 텍스트 입력창입니다.
* **`type="password"`:** 입력한 글자가 까만 점(●)이나 별표(*)로 가려져서 보이는 비밀번호 전용 입력창입니다.
* **`type="radio"`:** 여러 개의 보기 중 **단 하나만 선택**할 수 있는 동그란 버튼입니다. (예: 성별 선택, 객관식 문제)
* **`type="checkbox"`:** 여러 개의 보기를 **중복해서 선택**할 수 있는 네모난 버튼입니다. (예: 취미 다중 선택, 약관 동의)
* **`type="submit"`:** 이 버튼을 누르면 `<form>` 상자가 최종적으로 포장되어 서버(`action` 주소)로 전송(제출)됩니다.

> [!IMPORTANT]
> **서버가 데이터를 식별하는 이름표: `name` 속성**\
> `<input>` 태그를 만들 때는 반드시 **`name` 속성**을 달아주어야 합니다. 컴퓨터는 첫 번째 칸이 아이디인지 비밀번호인지 눈으로 봐서는 알 수 없습니다. 사용자가 입력한 값이 서버로 넘어갈 때, <b>`name="userId"`</b>처럼 정해둔 이름표가 붙어서 넘어가야만 서버가 올바르게 데이터를 인식하고 처리할 수 있습니다. 자바스크립트의 변수 이름과 같은 역할을 한다고 생각하면 됩니다.

```html
<form action="/signup" method="POST">
    <!-- 아이디 입력 (서버에는 username 이라는 이름표로 전달됨) -->
    아이디: <input type="text" name="username"> <br>
    
    <!-- 비밀번호 입력 (화면에 글자가 가려짐) -->
    비밀번호: <input type="password" name="userpw"> <br>
    
    <!-- 체크박스 (동의 체크 여부가 넘어감) -->
    <input type="checkbox" name="agree"> 약관에 동의합니다. <br>
    
    <!-- 제출 버튼 -->
    <input type="submit" value="회원가입 하기">
</form>
```
*(제출 버튼의 텍스트를 바꾸고 싶다면 `value="원하는 글자"`를 넣어주면 됩니다.)*

### 라디오 버튼 묶어주기 (Radio Grouping)
라디오 버튼은 "여러 개 중 하나만 선택"되어야 합니다. 컴퓨터에게 "이 3개의 버튼은 서로 같은 그룹의 문제야!"라고 알려주려면, <b>해당 라디오 버튼들의 `name` 속성값을 완벽하게 똑같이 맞추어 주어야 합니다.</b>

```html
<!-- name이 모두 'gender'로 같으므로, 셋 중 하나만 클릭할 수 있습니다! -->
<input type="radio" name="gender" value="male"> 남성
<input type="radio" name="gender" value="female"> 여성
<input type="radio" name="gender" value="none"> 선택안함
```
*(체크박스나 라디오 버튼은 사용자가 직접 키보드로 글씨를 치지 않으므로, 서버에 어떤 데이터가 넘어갈지 개발자가 미리 `value` 속성으로 지정해 두어야 합니다.)*

## 3. 라벨과 접근성의 마법: \<label\> 태그

위의 라디오 버튼 코드를 브라우저에서 실행해 보면 약간 불편한 점을 발견할 수 있습니다. 조그마한 동그라미 버튼을 마우스로 정확히 조준해서 클릭해야만 선택이 됩니다. 옆에 있는 "남성"이라는 글씨를 클릭하면 아무 반응이 없습니다.

이를 해결하고, 시각장애인용 리더기가 어떤 입력창인지 올바르게 읽게 만들어주는 태그가 바로 <b>`<label>`</b>입니다. 

`<label>`의 <b>`for` 속성</b>과, `<input>`의 <b>`id` 속성</b>을 똑같은 단어로 맞추어 연결해 주면, 텍스트(라벨)를 클릭해도 입력창이 활성화되는 마법 같은 기능이 생깁니다.

```html
<!-- input에 고유한 id를 부여하고, label의 for를 그 id와 일치시킵니다. -->
<input type="radio" name="gender" id="gen_male" value="male"> 
<label for="gen_male">남성</label> 

<!-- 이제 '여성'이라는 텍스트만 클릭해도 동그라미에 체크가 됩니다! -->
<input type="radio" name="gender" id="gen_female" value="female"> 
<label for="gen_female">여성</label> 
```

> [!TIP]
> 실무에서는 `id`와 `for`를 짝지어주는 방식도 쓰지만, 단순히 <b>`<label>` 태그 안에 `<input>`을 통째로 집어넣는 감싸기 방식</b>을 쓰면 `id`를 짓지 않아도 자동으로 연결되므로 훨씬 편리하게 코드를 작성할 수 있습니다.
> ```html
> <label>
>     <input type="checkbox" name="agree"> 약관에 동의합니다.
> </label>
> ```

## 4. 다양한 폼 요소 (textarea, select)

`<input>` 태그로는 해결할 수 없는 특수한 형태의 입력창들도 존재합니다.

### 여러 줄의 긴 글을 쓸 때: `<textarea>`
게시판의 본문이나 자기소개서처럼 엔터를 쳐가며 긴 글을 입력해야 할 때는 빈 태그가 아닌 시작과 종료 태그를 가진 `<textarea>`를 사용합니다.

```html
<!-- rows와 cols 속성으로 화면에 보여질 박스의 기본 크기를 줄/칸 단위로 정합니다. -->
<textarea name="introduce" rows="5" cols="30">
여기에 미리 적어둔 글은 기본 텍스트로 화면에 나타납니다.
</textarea>
```

### 드롭다운 선택 메뉴: `<select>`와 `<option>`
눌렀을 때 주르륵 메뉴가 밑으로 떨어지고, 그중 하나를 고르는 드롭다운를 만들 때 사용합니다. 목록 태그(`ul`, `li`)처럼 껍데기와 알맹이가 세트로 작동합니다.

* `<select>`: 드롭다운 메뉴의 껍데기입니다. 여기에 `name` 이름표를 붙입니다.
* `<option>`: 클릭 시 나타나는 각각의 선택지입니다. 여기에 서버로 전송할 `value`를 적습니다.

```html
<label for="color_select">좋아하는 색상:</label>
<select name="favoriteColor" id="color_select">
    <option value="red">강렬한 빨간색</option>
    <option value="blue">시원한 파란색</option>
    <!-- selected 속성을 넣으면 기본적으로 선택된 상태가 됩니다. -->
    <option value="green" selected>편안한 초록색</option> 
</select>
```

## 5. 알아두면 유용한 폼 보조 속성들

마지막으로, 폼의 사용성(UX)을 크게 높여주는 `<input>` 태그의 쏠쏠한 추가 속성들을 소개합니다.

* **`placeholder`**: 입력창에 회색 옅은 글씨로 <b>'입력 안내 문구'</b>를 띄워줍니다. 사용자가 글자를 타이핑하는 순간 자동으로 사라집니다.
* **`required`**: **필수 입력 항목**으로 지정합니다. 이 속성이 붙은 칸을 비워두고 제출(`submit`) 버튼을 누르면, 브라우저가 제출을 강제로 막고 "이 입력란을 작성하세요"라는 경고창을 띄워줍니다.
* **`readonly`**: 읽기 전용으로 만듭니다. 안에 적힌 글씨를 복사할 수는 있지만, 내용을 수정할 수는 없습니다.
* **`disabled`**: 입력창을 완전히 비활성화합니다. 클릭도 되지 않으며, 폼 제출 시 서버로 데이터가 넘어가지도 않습니다.

```html
<!-- 안내 문구가 있고, 반드시 작성해야만 제출되는 완벽한 입력창! -->
<label for="email">이메일 주소</label>
<input type="text" id="email" name="userEmail" placeholder="example@gmail.com" required>
```
