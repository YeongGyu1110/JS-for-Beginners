# 조건문 (if, else, 조건부 연산자)

## 개요
지금까지 우리가 작성한 코드는 위에서부터 아래로 한 줄씩, 단 한 줄도 빠짐없이 순서대로 실행되었습니다. 하지만 실제 프로그램은 상황에 따라 다른 행동을 취해야 합니다. "체력이 0 이하가 되면 게임 오버 화면을 띄운다", "로그인 상태라면 내 정보를 보여주고, 아니라면 로그인 버튼을 보여준다" 처럼 말입니다.

본 문서에서는 프로그램이 주어진 조건을 판단하여 <b>특정 코드를 실행할지 말지 결정하게 만드는 제어문(Control Flow)</b>의 가장 기본인 `if`문에 대해 학습합니다. 더불어 여러 조건을 연결하는 방법과, 코드를 짧게 줄여주는 조건부 연산자에 대해서도 알아봅니다.

### 이 모듈에서 배울 내용
* 특정 조건에서만 코드를 실행하는 `if`문의 기본 구조
* `if`문의 소괄호 안에서 일어나는 `Truthy`와 `Falsy` 자동 형변환
* 조건이 거짓일 때의 대안을 마련하는 `else` 절
* 여러 개의 조건을 순차적으로 검사하는 `else if` 절
* 짧고 간결하게 값을 결정할 수 있는 조건부 연산자(삼항 연산자)

---

## 1. if문 기본

`if`문은 영어 단어의 뜻("만약 ~라면") 그대로, <b>주어진 조건이 참(`true`)일 때만 중괄호 `{}` 안의 코드를 실행</b>하는 문법입니다. 

* `if` 뒤의 소괄호 `()` 안에는 참/거짓을 판별할 조건식을 적습니다.
* 중괄호 `{}` 안에는 조건이 참일 때 실행할 명령들을 적습니다. (이를 '코드 블록'이라고 부릅니다.)

```javascript
let playerLevel = 10;

// playerLevel이 5보다 크기 때문에 조건식은 true가 됩니다.
if (playerLevel > 5) {
    console.log("초보자 튜토리얼을 종료합니다.");
    console.log("새로운 맵이 열렸습니다!");
}

// 이 코드는 if문 바깥에 있으므로 조건과 상관없이 무조건 실행됩니다.
console.log("게임을 계속 진행합니다."); 
```

만약 `playerLevel`이 3이었다면 소괄호 안의 조건이 `false`가 되므로, 중괄호 안의 코드는 통째로 무시되고 건너뛰어집니다.

### 중괄호 생략
만약 조건이 참일 때 실행해야 할 명령이 **단 한 줄**뿐이라면, 중괄호 `{}`를 생략하고 작성할 수 있습니다. 코드를 더 짧게 만들고 싶을 때 유용합니다.

```javascript
let isReady = true;

// 실행할 코드가 한 줄이라면 중괄호를 생략할 수 있습니다.
if (isReady) console.log("게임을 시작합니다.");

// 줄바꿈을 해도 똑같이 작동합니다.
if (isReady) 
    console.log("게임을 시작합니다.");
```

## 2. if문 소괄호 안의 자동 형변환

비교 연산자(`>`, `===` 등)를 사용하면 결과가 자연스럽게 `true`나 `false`가 되지만, 만약 소괄호 안에 숫자나 문자열 같은 다른 데이터가 단독으로 들어가면 어떻게 될까요?

이때 <b>Truthy(참 같은 값)</b>와 <b>Falsy(거짓 같은 값)</b> 개념이 아주 중요하게 쓰입니다. `if`문의 소괄호는 <b>내부에 들어온 모든 값을 자동으로 논리형(Boolean)으로 형변환하여 판단</b>합니다.

* `0`, `""`, `null`, `undefined`, `NaN`과 같은 **Falsy 값**이 들어오면 `false`로 취급하여 코드를 실행하지 않습니다.
* 그 외의 내용물이 있는 모든 **Truthy 값**은 `true`로 취급하여 코드를 실행합니다.

```javascript
let currentHP = 0;

// currentHP는 0입니다. 0은 Falsy 값이므로 조건이 false가 되어 내부 코드가 실행되지 않습니다.
if (currentHP) {
    console.log("캐릭터가 아직 살아있습니다!");
}

let userName = "Hero";

// "Hero"는 비어있지 않은 문자열, 즉 Truthy 값이므로 true로 취급되어 코드가 실행됩니다.
if (userName) {
    console.log(`환영합니다, ${userName}님!`); // 이 코드는 실행됩니다.
}
```
이러한 특징 덕분에 실무에서는 어떤 변수에 값이 제대로 들어있는지(비어있지 않은지) 확인할 때 `if (변수이름)` 형태를 아주 자주 사용합니다.

## 3. else 절과 else if 절

조건이 참일 때 실행할 코드를 적었다면, 반대로 <b>조건이 거짓일 때 실행할 '플랜 B'</b>도 필요할 것입니다. 이때 `else`와 `else if`를 사용합니다.

### 조건이 거짓일 때: else
`else`는 `if`문의 조건이 거짓(`false`)일 때 실행되는 코드 블록입니다. `else` 뒤에는 별도의 소괄호(조건식)를 적지 않습니다. "위 조건이 아니라면 무조건 이것을 실행해라!"라는 뜻이기 때문입니다.

```javascript
let isRaining = true;

if (isRaining) {
    console.log("우산을 챙기세요.");
} else {
    console.log("날씨가 맑습니다. 산책을 나가보세요.");
}
```

### 여러 조건을 순서대로 검사할 때: else if
검사해야 할 조건이 두 가지를 넘어서 여러 개라면, `if`와 `else` 사이에 `else if`를 원하는 만큼 끼워 넣을 수 있습니다. 
컴퓨터는 <b>위에서부터 차례대로 조건을 검사하다가 참인 것을 발견하면 해당 블록만 실행하고 전체 if문을 즉시 빠져나갑니다.</b>

```javascript
let score = 85;

if (score >= 90) {
    console.log("A 등급입니다.");
} else if (score >= 80) {
    // 90점 미만이면서 80점 이상인 경우 이곳이 실행됩니다.
    console.log("B 등급입니다.");
} else if (score >= 70) {
    console.log("C 등급입니다.");
} else {
    // 위의 모든 조건이 거짓일 때 마지막으로 실행됩니다.
    console.log("재시험이 필요합니다.");
}
```

> [!NOTE]
> `else if`와 `else`는 필수가 아닙니다. 상황에 따라 `if`문 단독으로 써도 되고, `else` 없이 `else if`만 여러 개 나열해도 프로그램은 정상적으로 작동합니다.

## 4. 조건부 연산자 (삼항 연산자)

간단한 조건을 검사해서 변수에 각각 다른 값을 넣어야 할 때, `if`와 `else`를 사용하면 코드가 다소 길어집니다.

```javascript
let age = 20;
let isAdult;

// if-else를 사용한 값 할당
if (age >= 18) {
    isAdult = true;
} else {
    isAdult = false;
}
```

자바스크립트에서는 이런 단순한 분기 처리를 단 한 줄로 줄여 쓸 수 있는 <b>조건부 연산자</b>를 제공합니다. 피연산자가 3개라서 흔히 <b>삼항 연산자</b>라고도 부릅니다. 
물음표(`?`)와 콜론(`:`)을 사용합니다.

* **문법:** `조건식` ? `참일 때 반환할 값` : `거짓일 때 반환할 값`

```javascript
let userAge = 20;

// userAge >= 18 조건이 참이면 "성인", 거짓이면 "미성년자"라는 값이 할당됩니다.
let statusMessage = (userAge >= 18) ? "성인" : "미성년자";

console.log(statusMessage); // 출력: "성인"
```

> [!IMPORTANT]
> **삼항 연산자는 만능이 아닙니다!**
> 코드를 짧게 만들어주어 편리하지만, 삼항 연산자 안에 또 삼항 연산자를 꼬리 물기 하듯 중첩해서 작성하면 코드를 읽기가 극도로 힘들어집니다. 
> 
> * **단순히 값을 결정해서 변수에 넣을 때:** 삼항 연산자(`? :`) 사용을 권장합니다.
> * **코드가 길거나 여러 줄의 명령을 실행해야 할 때:** 기본 `if ... else`문 사용을 권장합니다.
> 
> 위와 같은 기준을 가지고 상황에 맞게 적절히 섞어 쓰는 것이 좋은 개발자의 습관입니다.
