# 비교 연산자

## 개요
프로그램을 만들다 보면 "플레이어의 체력이 0 이하인가?", "사용자가 입력한 비밀번호가 기존 비밀번호와 일치하는가?"처럼 두 개의 데이터를 비교하여 결정을 내려야 하는 순간이 반드시 찾아옵니다.

본 문서에서는 두 값을 비교하여 참(`true`) 또는 거짓(`false`)을 반환하는 <b>비교 연산자</b>에 대해 알아봅니다. 기본적인 숫자 비교부터 시작해서 자바스크립트가 문자를 비교하는 방식, 서로 다른 자료형을 비교할 때 일어나는 일, 그리고 자바스크립트의 가장 큰 특징 중 하나인 동등 연산자(`==`)와 엄격한 일치 연산자(`===`)의 차이에 대해 상세히 다룹니다.

### 이 모듈에서 배울 내용
* 기본 연산자 (`>`, `<`, `>=`, `<=`)
* 자바스크립트가 문자열의 크기를 비교하는 원리 (사전순)
* 서로 다른 자료형을 비교할 때 발생하는 자동 형변환
* 값만 비교하는 동등 연산자(`==`)와 타입까지 비교하는 일치 연산자(`===`)
* `null`과 `undefined`를 비교할 때 발생하는 특수한 규칙과 주의점

---

## 1. 기본 비교 연산자

가장 기본적인 형태의 비교 연산자입니다. 수학 시간에 배웠던 부등호와 완전히 같은 역할을 하며, 연산의 결과는 항상 <b>불리언(Boolean) 값인 `true`나 `false`</b>가 됩니다.

* `a > b` : a가 b보다 크다 (초과)
* `a < b` : a가 b보다 작다 (미만)
* `a >= b` : a가 b보다 크거나 같다 (이상)
* `a <= b` : a가 b보다 작거나 같다 (이하)

```javascript
console.log(10 > 5);  // 출력: true
console.log(10 < 5);  // 출력: false
console.log(10 >= 10); // 출력: true
```

## 2. 문자열의 비교

자바스크립트는 숫자뿐만 아니라 문자열끼리도 크기를 비교할 수 있습니다. 이때 흔히 사람이 아는 '사전순'으로 비교한다고 오해하기 쉽지만, 정확하게는 각 문자에 부여된 <b>'유니코드(Unicode) 코드 포인트 값'</b>을 기준으로 크기를 결정합니다. 

즉, 눈에 보이는 글자가 아니라 컴퓨터 내부적으로 할당된 고유한 **숫자 값**을 차례대로 비교하는 방식입니다.

1. 문자열의 첫 번째 글자가 가진 유니코드 숫자를 비교하여 큰 쪽을 더 크다고 판별합니다.
2. 첫 번째 글자가 같다면 두 번째, 세 번째 글자의 유니코드 값을 순서대로 비교합니다.

```javascript
// 'Z'의 유니코드 값(90)이 'A'의 유니코드 값(65)보다 크므로 "Z"가 더 큽니다.
console.log("Z" > "A"); // 출력: true

// 앞의 'G'와 'l'은 똑같지만, 세 번째 글자 'o'의 유니코드 값이 'e'보다 크므로 "Glow"가 더 큽니다.
console.log("Glow" > "Glee"); // 출력: true
```

> [!NOTE]
> **대문자와 소문자의 비교**
> 현실의 영어 사전에서는 대문자와 소문자의 순서 차이가 없지만, 유니코드 표에서는 **대문자가 소문자보다 먼저(더 작은 숫자로) 배치**되어 있습니다. (예: `A`는 65, `a`는 97) 따라서 자바스크립트에서는 소문자가 대문자보다 무조건 더 큰 값으로 취급됩니다.
> ```javascript
> // 'a'의 유니코드 값(97)이 'A'의 유니코드 값(65)보다 큽니다.
> console.log("a" > "A"); // 출력: true
> ```

## 3. 서로 다른 자료형의 비교 (자동 형변환)

비교하려는 두 값의 자료형이 다르면 자바스크립트는 비교를 위해 <b>값들을 숫자형(Number)으로 몰래 자동 변환</b>한 뒤에 비교를 수행합니다.

```javascript
// 문자열 "2"가 숫자 2로 변환된 후 비교됩니다.
console.log("2" > 1); // 출력: true

// 문자열 "01"이 숫자 1로 변환된 후 비교됩니다.
console.log("01" == 1); // 출력: true

// true는 1로, false는 0으로 변환된 후 비교됩니다.
console.log(true > 0); // 출력: true
console.log(false == 0); // 출력: true
```

편리해 보일 수 있지만, 이러한 '자동 형변환'은 개발자가 예상치 못한 치명적인 버그를 만들어내는 주범이기도 합니다. 이를 막기 위해 존재하는 것이 바로 아래에서 설명할 **일치 연산자**입니다.

## 4. 동등 연산자(==) vs 일치 연산자(===)

두 값이 "같은지" 비교할 때, 자바스크립트는 두 가지 방식의 연산자를 제공합니다. 이 둘의 차이를 명확히 이해하는 것은 매우 중요합니다.

### 동등 연산자 (==, !=)
`==`는 값이 같은지 확인하고, `!=`는 값이 다른지 확인합니다. 이 연산자는 <b>자료형이 다르면 강제로 형변환을 한 뒤에 값을 비교(느슨한 비교)</b>합니다.

```javascript
// 숫자 0과 빈 문자열, 그리고 false는 형변환 시 모두 0으로 취급됩니다.
console.log(0 == false); // 출력: true
console.log("" == false); // 출력: true
console.log("100" == 100); // 출력: true
```
얼핏 보면 같아 보여서 `true`가 나오는 것이 당연해 보이지만, 자료형이 엄연히 다른데도 같다고 판별해버리기 때문에 데이터가 꼬이기 쉽습니다.

### 엄격한 일치 연산자 (===, !==)
이 연산자는 <b>값뿐만 아니라 자료형(Type)까지 완벽하게 똑같은지 비교(엄격한 비교)</b>합니다. 형변환을 절대 일으키지 않습니다.

```javascript
// 값은 같아 보일지 몰라도, Number와 Boolean으로 자료형이 다르므로 false입니다.
console.log(0 === false); // 출력: false
console.log("" === false); // 출력: false

// 자료형(String)과 값("100")이 모두 같아야 true가 됩니다.
console.log("100" === "100"); // 출력: true
console.log("100" === 100);   // 출력: false
```

## 5. null과 undefined의 비교

자바스크립트에서 '비어있음'을 나타내는 `null`과 `undefined`를 비교할 때는 수학적인 논리가 통하지 않는 자바스크립트만의 아주 특이한 규칙이 적용됩니다.

### 일치 연산자 (===)를 쓸 때
두 값은 엄연히 다른 자료형이므로 거짓(`false`)이 됩니다.
```javascript
console.log(null === undefined); // 출력: false
```

### 동등 연산자 (==)를 쓸 때
자바스크립트는 특별한 규칙을 두어 **`null`과 `undefined`가 서로 동등 연산자(`==`)로 비교될 때만 `true`를 반환**하도록 묶어두었습니다. 이들은 서로 격하게 사랑하는 커플과 같아서 다른 어떤 값(0이나 false 등)과 비교해도 무조건 `false`를 뱉지만, 자기들끼리 비교할 때만 `true`를 뱉습니다.

```javascript
console.log(null == undefined); // 출력: true
console.log(null == 0);         // 출력: false
```

### 크기 비교 연산자 (>, <, >=, <=)를 쓸 때
하지만 크기를 비교하는 부등호 연산자를 만나면 **자동 형변환**이 일어나면서 `null`은 숫자 `0`으로 변환됩니다. 여기서 자바스크립트의 유명한 괴상한 결과가 탄생합니다.

```javascript
console.log(null > 0);  // 출력: false (0 > 0 은 거짓)
console.log(null == 0); // 출력: false (동등 연산자는 null을 undefined하고만 같다고 취급함)
console.log(null >= 0); // 출력: true  (크기 비교 연산에 의해 null이 0으로 변환되어 0 >= 0 이 되므로 참!)
```

> [!TIP]
> `null`이나 `undefined`가 변수에 들어있을 가능성이 있다면, 부등호(`<`, `>`)로 크기를 비교하는 코드를 작성하기 전에 이 값들이 비어있는지 먼저 확인하는 방어적인 코드를 작성해야 이런 황당한 버그를 피할 수 있습니다.
